# Initial DORK document drafts

Prepared 2026-09-30. These Markdown files are tentative authoring sources stored with the NERD repository. They are not Active DORK records and have not been published to SharePoint. GitHub tracks revisions while the documents are developed; SharePoint remains the intended authoritative DORK record when they are converted.

These are recommendations, not approved taxonomy changes or newly allocated document IDs. The Framework governs the organization, ownership and authority of operational knowledge, so Data Governance is its proposed Function. Its type remains Standard, consistent with the previously used classification and its required structural/operating specifications. The operations document explains how Technology staff carry out those rules; Procedure reflects that purpose.

The original [v0.2 extracted text](framework-v0.2-source-extract.md) is retained for comparison. Its parsed tables are not a replacement for the original Word layout.

## Editing and conversion

1. Develop and review these sources in GitHub. Keep policy intent separate from completed software behavior.
2. Resolve open Framework policy questions, especially Owner-or-Responsible versus Owner activation approval. Do not silently change the policy to match the current UI.
3. Confirm proposed classifications, final titles, ownership, Classification and contextual review requirements.
4. Once initial DORK documents can be created reliably, convert each source into its appropriate template/format. Include or retain the complete controlled taxonomy reference with the Framework.
5. Allocate permanent IDs through the verified numbering workflow; only the Framework's 0001 reservation is decided.
6. Replace draft relative links with managed DORK associations/stable links where supported. Do not invent SharePoint links before the documents exist.
7. Verify complete content, metadata, permissions and page representations, then obtain the required activation approval.
8. Record the resulting authoritative DORK locations here. Do not maintain conflicting Active copies in GitHub and SharePoint.

[Implementation checklist](../framework-implementation-checklist.md) records software/tenant acceptance work. [Permanent numbering plan](../permanent-numbering.md) records allocation gates.

## Known publication gates

Owner approval enforcement, numbering, overdue presentation, managed replacement links, backlog implementation and tenant security/search/recovery checks remain incomplete or unverified. The drafts describe intended practices without presenting those features as deployed.
